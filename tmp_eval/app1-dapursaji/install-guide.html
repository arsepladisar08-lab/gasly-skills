MANDIRI / OFFLINE

Panduan ini membantu memasang backend dan frontend DapurSaji. File panduan tidak memuat library, font, gambar, stylesheet, atau script eksternal. Tautan dokumentasi resmi hanya dibuka jika Anda memilihnya.

Langkah 1 — Spreadsheet & backend GAS

Tujuan: Menyiapkan database utama dan editor Apps Script container-bound.
Aksi: Buat Google Spreadsheet baru. Dari URL Spreadsheet, salin bagian ID di antara /d/ dan /edit ke parameter di atas. Buka Extensions > Apps Script. Buat atau buka file setup.gs dan code.gs, lalu tempel isi file proyek masing-masing dan simpan.
Hasil yang diharapkan: Kedua file backend tersimpan tanpa error sintaks.
Sumber: Dokumentasi bound scripts; katalog langkah instalasi.
Last Verified: UNVERIFIED — jalur menu UI dicatat untuk pemeriksaan manual.
Tautan Spreadsheet untuk diperiksa / disalin
Isi Spreadsheet ID pada form konfigurasi di atas.
Pastikan nama file dan isi kode tetap sesuai keluaran proyek. Jangan mengganti skema database dengan contoh dari proyek lain.

Langkah 2 — Setup environment 1-klik

Tujuan: Menjalankan initialSetupDatabase() melalui entrypoint setup, menginisialisasi skema, serta membuat rahasia sistem dan folder Drive jika belum tersedia.
Aksi: Di toolbar Apps Script, pilih setupAppEnvironment lalu klik Run. Setujui dialog otorisasi Google. Tunggu hingga eksekusi selesai dan buka Execution Log.
Hasil yang diharapkan: Laporan setup menunjukkan READY_TO_DEPLOY setelah seluruh kredensial admin diatur; periksa juga sheetsHealthy, hmacSecretReady, pepperReady, dan driveRootReady.
Sumber: references/config.md Seksi 2–3; daftar kontrak entitas.
Last Verified: UNVERIFIED — jalur toolbar UI.
Jangan membuat manual: AUTH_HMAC_SECRET, AUTH_PEPPER, atau DRIVE_ROOT_FOLDER_ID. Inisialisasi server membuat dan mengelolanya. Folder bukti pesanan harus tetap privat.

Kontrak database DapurSaji mencakup:

  • ORDERS — data pelanggan dan pesanan, klasifikasi SENSITIVE_PII, unggahan Drive privat.
  • ORDER_ITEMS — snapshot item pesanan, klasifikasi CONFIDENTIAL.
  • CATALOG — data katalog publik, klasifikasi PUBLIC.

Langkah 3 — ScriptProperties & kredensial admin

Tujuan: Menyimpan kredensial admin DapurSaji sebagai hash server-side dan menetapkan profil akses P3.
Aksi: Buka Project Settings (ikon roda gigi) > Script Properties. Tambahkan properti sementara ADMIN_PASSPHRASE_INIT dengan passphrase pilihan Anda minimal 12 karakter dan ADMIN_PIN_INIT dengan PIN pilihan Anda tepat 6 digit. Tambahkan ACCESS_PROFILE dengan nilai P3. Simpan. Kembali ke editor, pilih fungsi setupAdminCredentials() pada toolbar lalu klik Run.
Hasil yang diharapkan: Properti hash dan salt admin tersimpan. ADMIN_PASSPHRASE_INIT dan ADMIN_PIN_INIT terhapus otomatis. Tidak ada plaintext kredensial di file .gs, HTML, atau Spreadsheet.
Sumber: references/config.md; references/install-steps.md; Script Properties.
Last Verified: UNVERIFIED — jalur UI pihak ketiga.
Keamanan kredensial: Jangan menulis passphrase atau PIN ke source code, chat, file konfigurasi frontend, log, atau sel Spreadsheet. Jangan mengirim kredensial admin melalui parameter URL. Jalankan setupAdminCredentials() setelah properti sementara disimpan, lalu pastikan kedua properti init sudah hilang.

Langkah 4 — Deploy Web App /exec

Tujuan: Menyediakan endpoint backend yang bisa dipanggil frontend statis lintas domain.
Aksi: Pastikan setup database dan kredensial admin selesai. Di editor Apps Script, klik Deploy > New deployment, pilih Web app, set Execute as: Me dan Who has access: Anyone, lalu Deploy. Salin URL berakhiran /exec ke parameter panduan.
Hasil yang diharapkan: URL Web App valid dengan host script.google.com dan path yang memuat /macros/ serta berakhir /exec.
Sumber: references/config.md Seksi 3; Apps Script Web Apps.
Last Verified: UNVERIFIED — langkah menu UI dicatat untuk verifikasi manual.
Zero-downtime update: Untuk perubahan kode berikutnya, gunakan Deploy > Manage deployments > Edit (ikon pensil) > Version: New version > Deploy. Jangan membuat deployment baru jika ingin URL /exec tetap sama.
URL endpoint setelah diisi
Isi URL Web App /exec di parameter konfigurasi di atas.

Request aplikasi harus menggunakan metode POST dengan Content-Type: text/plain;charset=utf-8 dan body JSON berbentuk { action, v: 1, auth, idem, payload }. Jangan mengirim header Authorization atau Content-Type application/json karena dapat memicu preflight OPTIONS yang tidak dilayani GAS.

A. Pilih stack frontend

Stack proyek DapurSaji adalah html-tailwind. File utama konfigurasi: src/config.js. Contoh berikut hanya pola nilai endpoint, bukan pengganti seluruh isi file.

Snippet nilai konfigurasi frontend
window.GASLY_CONFIG = {
  EXEC_URL: '{{GAS_EXEC_URL}}'
};

Jangan menghapus properti lain yang mungkin sudah digunakan gasClient.js atau aplikasi. Gabungkan URL ke struktur konfigurasi aktual, bukan menimpa file tanpa memeriksa isinya.

Domain publik dan status OAuth (OAuth nonaktif pada DapurSaji)
PAGES_DOMAIN={{PAGES_DOMAIN}}
GOOGLE_CLIENT_ID={{GOOGLE_CLIENT_ID}} (tidak digunakan; Google Sign-In nonaktif)

Panel ini hanya referensi jika arsitektur frontend kelak dimigrasikan ke React/Vite. Tidak berlaku untuk daftar file DapurSaji saat ini.

Contoh konfigurasi environment React/Vite
VITE_GAS_EXEC_URL={{GAS_EXEC_URL}}

Jangan membuat file .env atau menjalankan build React pada proyek html-tailwind ini tanpa migrasi stack yang disengaja.

Langkah 6 — Diagnostik & uji koneksi

Tujuan: Memastikan backend siap dan endpoint Web App merespons dengan envelope kanonik.
Aksi: Di Apps Script jalankan runDiagnostics() dan pastikan ok: true. Setelah itu pilih alat uji di bawah, salin snippet, lalu jalankan sendiri. Panduan ini tidak memanggil endpoint.
Hasil yang diharapkan: Respons berbentuk { status, code, data, message, meta }, dengan status success atau error dan kode sesuai kontrak.
Sumber: Kontrak DapurSaji envelope_spec dan action catalog.list; references/install-steps.md; references/gates.md.
Last Verified: 2026-11-25 untuk fakta runtime/HTTP; diagnostik proyek harus dijalankan pemilik.
Endpoint GAS dapat mengembalikan HTTP 302 dan dialihkan ke script.googleusercontent.com. Gunakan curl -L atau opsi redirect follow pada pengujian manual. Request browser memakai POST dan text/plain;charset=utf-8.
Salin dan jalankan di terminal macOS / Linux / Git Bash
curl -sL -X POST '{{GAS_EXEC_URL}}' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  -d '{"action":"catalog.list","v":1,"auth":null,"idem":null,"payload":{}}'
Salin dan jalankan di Windows PowerShell
$body = '{"action":"catalog.list","v":1,"auth":null,"idem":null,"payload":{}}'
Invoke-RestMethod -Method Post -Uri '{{GAS_EXEC_URL}}' -ContentType 'text/plain;charset=utf-8' -Body $body
Salin dan jalankan sendiri di DevTools Console domain frontend
fetch('{{GAS_EXEC_URL}}', {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' },
  redirect: 'follow',
  body: JSON.stringify({ action: 'catalog.list', v: 1, auth: null, idem: null, payload: {} })
}).then(function (response) { return response.json(); }).then(console.log);

Checklist uji fungsi DapurSaji

  • catalog.list: katalog publik dapat dibaca.
  • order.create: uji pembuatan pesanan pada lingkungan yang sesuai; action ini wajib membawa idempotency key sesuai implementasi backend.
  • order.track: uji hanya dengan token pelacakan berentropi tinggi yang diterbitkan server; jangan menguji enumerasi ID pesanan.
  • file.ticket lalu file.upload: uji unggah bukti milik pemesan dengan tiket dan idempotency key; pastikan Drive tetap private.
  • auth.login, order.adminList, order.updateStatus, file.adminView, dan catalog.save: uji setelah autentikasi admin berhasil.
  • auth.logout: uji sesi admin berakhir.
Privasi: Jangan menyalin respons yang berisi data pribadi pelanggan ke issue publik, forum, atau chat. Jangan pernah membuka bukti pembayaran melalui URL publik atau mengubah izin folder menjadi Anyone with link.

Troubleshooting

POST menghasilkan HTTP 302

Redirect GAS adalah perilaku yang dapat terjadi pada Web App. Ikuti redirect saat menjalankan uji manual dengan curl -L atau redirect: 'follow'.

Browser menampilkan CORS atau preflight OPTIONS gagal

Gunakan POST dengan Content-Type: text/plain;charset=utf-8. Letakkan auth dan idem di body JSON, bukan header khusus. Hindari application/json.

Halaman meminta otorisasi Google atau menampilkan HTML, bukan JSON

Periksa pengaturan deployment Web App: Execute as: Me dan Who has access: Anyone. Pastikan URL yang dipakai adalah URL deployment berakhiran /exec.

Perubahan kode backend tidak muncul

Gunakan Deploy > Manage deployments > Edit > New version > Deploy. Jangan membuat deployment baru jika URL lama harus dipertahankan.

Upload bukti pesanan gagal

Pastikan tiket upload masih valid, file sesuai batas ukuran dan MIME yang diterima backend, serta respons file.upload benar-benar sukses sebelum UI menampilkan status berhasil. Bukti pesanan disimpan privat.

Setup belum menunjukkan READY_TO_DEPLOY

Baca actionsRequired pada Execution Log. Pastikan properti init kredensial disetel dengan benar, jalankan setupAdminCredentials(), lalu jalankan ulang setupAppEnvironment() untuk memeriksa kesiapan.
